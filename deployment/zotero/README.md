# Research Assistant Bridge for Zotero

## Qwen API 配置（开发中）

- 面板填写 HTTPS 地址（以 `/v1` 或完整 `/v1/embeddings` 结尾）、密钥、服务实际模型名、输出维度和模型版本标识。维度须与服务返回值相同；同名模型更换权重时更新版本标识。
- 适配 `vLLM Qwen3-VL messages`，文字／图片／图文均从同一模型取向量；不是聊天接口，也不保证任意供应商的 OpenAI-compatible 接口支持此扩展。
- 配置按请求传入；已开始任务保留启动时配置。模型配置变化使用新 Qdrant collection，旧数据保留。未配置仍保留原自托管路径；显式配置失败不会偷偷改用旧 Qwen。
- 首次检索仅编码当前所选来源，可能产生费用；不同来源组合使用隔离索引。没有自动重试；完整索引可复用，但失败建库重试或切换重叠来源组合仍可能重复计费。不要用全库做首次连通验证。
- 本轮仅完成代码；未真实调用 API、未测试或安装新插件。LLM 配置已传到模型构造，MinerU 本地／远端配置已接入后台精析，原服务未停止。详见 [本地启动与部署](../../docs/deployment/本地主后端与远端Qwen.md)。

协议依据：[用户指定的固定版本教程](https://github.com/gcanlin/vllm-ascend/blob/7945cd6c8aa4b1c7d4f6fa7c9d81e50c2cef69f1/docs/source/tutorials/Qwen3_vl_embedding.md)（文本）与 [vLLM 官方图文示例](https://github.com/vllm-project/vllm/blob/main/examples/pooling/embed/vision_embedding_online.py) 中的 `run_qwen3_vl`（补充图文；main 会变化，最终以实际服务版本验收）。

一个面向 Zotero 9 的轻量科研助手桥接插件。它将用户明确选择的 Zotero 分类同步到科研助手后端，并保留 PDF、批注和笔记之间的来源关系。

## 当前版本

- 插件版本：`0.3.0`
- 支持 Zotero：`9.x`
- 插件 ID：`research-assistant@local`
- 状态：Zotero 内部工作台测试版本

## 功能

- 按 Zotero 分类创建独立知识库。
- 在 Zotero 内部窗口完成检索、资料查看和专题笔记编辑，不再打开外部浏览器。
- 可配置并自动启动本机 Python 科研引擎。
- 可选择是否包含当前分类的子分类。
- 同步分类中的 PDF、PDF 批注和 Zotero 笔记。
- 相同 PDF 按内容哈希去重，可同时属于多个知识库。
- 在多个知识库中联合检索，并区分原文、批注和笔记来源。
- 问答通过持久化异步任务执行：Zotero 先取得任务 ID，再轮询状态；服务重启会显示中断，不会自动重发可能已计费的请求。
- 工作台提供“问答历史”：可以查看最近任务的状态、失败原因，并直接打开已保存的回答；打开历史不会再次调用模型。
- 失败或服务重启中断的任务可在历史中明确点击“手动重试”；每条任务链最多 3 次，成功任务不会重复提交。
- 从 Zotero 阅读器选区打开科研知识库检索。
- 在资料列表勾选 2–4 篇 PDF，按研究条件进行多文献对照并跳转原文证据。
- 将已确认的专题笔记新增回 Zotero。
- 相同笔记修订不会重复写回，不覆盖已有 Zotero 笔记。
- 刷新保留未保存的编辑内容；切库、取消或改编另一条笔记前提示放弃确认，保存期间禁止切换编辑目标。
- 点击专题笔记引用直接显示回答当时使用的 revision、正文与来源；已更新或归档时明确提示，不用最新内容替换历史依据。

## 安装

1. 在仓库的 **Releases** 页面下载最新的 `.xpi` 文件。
2. 打开 Zotero。
3. 进入 **工具 → 插件**。
4. 点击插件管理页面右上角的齿轮按钮。
5. 选择 **Install Add-on From File / 从文件安装插件**。
6. 选择下载的 `research-assistant-0.3.0.xpi`。
7. 按 Zotero 提示完成安装；如有提示，请重启 Zotero。

## 配置后端

插件不是独立的检索服务器，需要连接 Research Assistant 后端。

1. 启动科研助手 Web 服务。
2. 在 Zotero 中进入 **工具 → 科研知识库 → 配置后端连接**。
3. 输入后端地址，例如：

   ```text
   http://127.0.0.1:8765
   ```

4. 输入后端生成的连接令牌。
5. 插件会调用状态接口验证连接，成功后保存当前配置。

连接地址只允许：

- 本机 `http://127.0.0.1`、`http://localhost` 或 `http://[::1]`。
- 使用 HTTPS 的远程服务器。

地址中不能包含用户名、密码、查询参数或 URL fragment。

## 同步分类

1. 在 Zotero 左侧选择一个具体分类。
2. 进入 **工具 → 科研知识库 → 同步当前分类**。
3. 选择是否包含子分类。
4. 阅读并确认数据发送提示。
5. 等待同步完成。

插件只会同步本次选定分类中的受支持内容。同步期间如果分类内容发生变化，本次提交会终止，避免以不一致快照替换知识库成员。

## 打开知识库

完成同步后，进入：

```text
工具 → 科研知识库 → 打开知识库
```

插件会直接打开 Zotero 内部的科研助手工作台，并定位到最近同步的知识库，不会跳转到外部浏览器。

在 Zotero PDF 阅读器中选中文字时，也可以使用 **在科研知识库中检索**。

## 将笔记写回 Zotero

1. 在科研助手中创建并确认专题笔记。
2. 回到 Zotero。
3. 进入 **工具 → 科研知识库 → 将知识库笔记新增到 Zotero**。
4. 确认写回数量和目标分类。

写回操作遵循以下规则：

- 只写回已确认且未归档的笔记。
- 只新增笔记，不覆盖现有笔记。
- 使用笔记 ID 和修订号标记，同一修订不会重复写回。

## 知识库备份与恢复

工作台“导出备份”包含 PDF 原件、分类、原生笔记/批注、专题笔记全部 revision，以及存在时的问答统计。恢复到新目录：

```powershell
python -m research_assistant.knowledge.backup --archive backup.zip --target recovered-library
```

命令会核对文件哈希、数据库完整性和表结构；已有目标目录直接拒绝。导出失败保留原有备份。恢复后数据位于 `recovered-library/.data/zotero`，不会覆盖在线数据库，不调用模型。

这是 **Zotero 知识库备份**：不包含连接令牌、`.env`、问答任务/反馈库、向量缓存、网页阅读器笔记或翻译产物；不能当作整机备份。恢复后的新实例需要重新配置连接，向量索引可以重建。

## 隐私与安全

- 插件不会自动上传整个 Zotero 资料库。
- 只有用户选择分类并确认后，相关 PDF、批注和笔记才会发送到配置的后端。
- 插件不会读取其他插件保存的翻译密钥。
- 插件不会自动调用全文翻译或生成模型。
- 单个 PDF 最大上传大小为 25 MB。
- 未下载到本机的附件不会被静默跳过；本次同步会明确失败。
- 连接令牌不会放在知识库页面的普通 URL 查询参数中。

在使用远程服务器前，请确认服务器由你信任，并了解文献数据的存储位置和访问控制。

## 从源码构建

独立插件仓库根目录应包含：

```text
README.md
manifest.json
bootstrap.js
bridge.js
assistant.xhtml
assistant.css
assistant.js
build.py
```

在插件仓库根目录运行：

```powershell
python build.py
```

生成文件（当前候选版）：

```text
output/zotero/research-assistant-0.3.0.xpi
```

XPI 是 ZIP 格式，正式包只包含：

```text
manifest.json
bootstrap.js
bridge.js
assistant.xhtml
assistant.css
assistant.js
```

## 已知限制

- 当前版本只支持 Zotero `9.x`。
- 插件需要配套的 Research Assistant 后端，不能单独完成解析和检索。
- 当前 `update_url` 指向仓库内的 `updates.json`；只有在该文件随 Release 一并更新后，插件内自动更新才会生效。
- 云盘自动上传和 WebDAV 凭据配置尚未接入。
- 原生隔离验收通过，但尚未把真实用户 Zotero 库的长期使用质量当作统计结果；应先用少量真实资料进行人工核对。
- 原生 fixture 使用 Zotero 9 的 `--start-debugger-server 2832`，不要使用旧的 `-jsdebugger` 连接脚本。
- 可复现入口为 `benchmarks/run_zotero_native_fixture.ps1`；它会先等待 8771 夹具服务和 2832 调试端口 ready，并拒绝接管已被占用的端口。

## 发布新版本

1. 修改 `manifest.json` 中的版本号。
2. 同步更新仓库根目录 `updates.json`：新增对应版本条目和 `update_link`。
3. 运行插件测试和知识库测试（`node --test tests/zotero_bridge.test.cjs` 会校验两者版本一致）。
4. 重新执行构建脚本；构建使用固定时间戳，同一份源码的 SHA-256 可复现。
5. 记录脚本输出的 SHA-256。
6. 在 GitHub 创建与版本号一致的标签，例如 `v0.3.0`；CI 会自动构建并附加 XPI。
7. 在 Release 说明中列出主要改动、兼容版本、验证结果和已知限制。
