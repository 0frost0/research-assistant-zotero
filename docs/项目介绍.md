## 1. 这个项目究竟是什么

它是围绕你自己的文献建立的科研证据工作台：把 PDF 等资料转成有出处的内容，让你寻找证据、提出问题、比较多篇研究，并检查系统有没有找到合适的依据。

普通聊天是“问模型知道什么”；这里的主要任务是“在我选定的文献中找到依据，并说明这些依据支持什么、不能支持什么”。因此，资料管理、文档结构、检索质量、证据出处和模型回答同样重要。

目前重点是文献问答和多文献对照。项目已经有研究计划工作台，但暂时保留现状，后续再重构。系统不会代你执行实验、训练模型、登录科研网站或自动修改论文，也不应直接用于未经核验的临床决策。

## 2. 你能用它做什么

| 工作 | 当前能力 | 结果与限制 |
| --- | --- | --- |
| 管理资料 | 上传、选择、删除 PDF/Markdown/TXT | 用户控制参与本次回答的资料范围 |
| 处理 PDF | 快速文字提取，或远程 MinerU 精析 | 保存正文、图片、表格和页码等结构；提取不保证完全准确 |
| 查找证据 | 统一多模态检索；可切换文字基线 | 同时定位正文和图片，保留出处及质量提示 |
| 文献问答 | 从命中证据生成回答 | 有依据才回答，不等于全文精读 |
| 多文献对照 | 2–4 篇按篇分析、并行综合、单轮复核 | 展示共识、差异和不可比之处，保留待核实内容 |
| 查表 | 结构化单元格、关键词和受限只读 SQL | 便于精确定位，跨页拼接与数值仍需校验 |
| 检查检索质量 | 分组评测、Recall@K、MRR、页码召回、AI 辅助与人工审阅 | 区分检索表现、AI 判断和真正的人工确认 |

主页是资料管理与问答入口；`/lab` 是评测与表格工作区；`/projects` 是暂缓扩展的研究计划工作区。

## 3. 整个系统由谁负责什么

项目不是“一个大模型加一个数据库”。关键组件分工如下：

| 组件 | 职责 | 它不负责什么 |
| --- | --- | --- |
| 网页与 Starlette 后端 | 接收问题、资料选择、执行请求和展示状态 | 不凭页面勾选直接认定科研结论正确 |
| MinerU | 理解 PDF 版面并提取结构化内容 | 不自动建成本项目的向量索引，也不保证图表数值无误 |
| Qwen3-VL-Embedding-2B | 把文字、图片和问题编码为可比较的向量 | 不负责撰写最终答案 |
| Qdrant | 存储向量、按相似度和过滤条件寻找候选 | 不保存所有文献原件，也不判断结论真假 |
| SQLite | 保存证据、版本、单元格、评测和业务状态 | 不是基础语言模型 |
| DeepSeek | 基于选出的证据做分析、综合和复核 | 当前不直接读取图片像素，也不能弥补缺失证据 |
| LangChain / LangGraph | 模型与结构化输出接口、状态流转、并行分工 | 不是新的基础模型，不自带科学正确性保证 |

这套分工的价值在于可定位问题。例如，一张表的数字错了，应先检查解析；正确段落没有被找到，应检查检索；证据正确但答案夸大，则应检查生成与复核。不能把所有问题都归因于“模型不够聪明”。

## 4. 文献从文件变成可检索证据

```text
原始文件
  -> 快速解析 / MinerU 精析
  -> 带来源、页码、类型、坐标的内容块
  -> 切块与图片资产整理
  -> SQLite 保存内容及版本
  -> Qwen 将正文或图片+图注编码
  -> Qdrant 保存统一空间中的向量
```

### 4.1 原件和解析产物分别保留

原件存于 `library/`，不是把 PDF 直接塞进向量数据库。快速路径以 `pypdf` 提取文字，必要时借助 OCR；它对复杂版式、公式和图表存在明显限制。

“精析”通过 SSH 隧道使用远程 GPU 上的 MinerU。本机保存其内容列表、Markdown、布局和图片等产物，并按文档内容缓存。随后将内容列表规范化为带有来源、页码、bbox、内容类型和图片关联的 Document。

精析和向量化是两个环节。完成解析会使原索引缓存失效；下一次检索时，根据当前内容和模型信息建立或更新对应索引，不需要每问一次就重新解析整篇论文。

### 4.2 切块既影响召回，也影响理解

当前共用基线是 450 字符窗口、80 字符重叠。块越短，定位往往更细，但可能拆开完整论证；块越长，信息更完整，也可能混入不相关主题。这是文档工程问题，不是模型向量维度的问题。

默认统一检索的后处理会尽可能补回同一原始块的上下文，上限 1800 字符。它核对来源、页码、坐标和文字匹配，不是随便拼接附近段落；匹配不唯一时不扩展。当前还不能保证跨页论证或跨页表格完整。

### 4.3 文字和图片使用同一个嵌入模型

默认使用 `Qwen/Qwen3-VL-Embedding-2B`，输出 2048 维归一化向量。正文作为文字输入；图片像素和已有图注作为联合输入；问题也由同一套模型权重编码。

因此，这不是把 BGE 文字向量和另一个图片模型的向量硬放在一起。统一多模态模型通过其训练建立了跨模态表征空间，本项目沿用官方编码处理方式，再把同空间向量放入同一 collection。查询与资料的任务提示可以不同，但没有换模型。

“坐标空间一致”仍不等于“科研检索一定准确”。专业术语、长文本、图表细节、中英文和不同模态都可能有偏差，所以仍要评测。Qdrant 中保留着历史实验集合；默认路径选用当前指纹匹配的集合，不会把不同模型空间混着比较。

### 4.4 更新资料时避免新旧证据混用

SQLite 保存文档激活版本，Qdrant 保存对应向量。更新采用“暂存新证据、写完新向量、激活新版本、清理旧向量”的顺序。查询命中后还回 SQLite 检查激活状态。

模型身份、维度和服务指纹也必须匹配。切换嵌入模型不能继续把旧向量当新模型的输出使用；新模型空间使用独立集合。未变化资料则复用已有向量，减少重复编码。

## 5. 普通文献问答如何工作

```text
问题 + 选用资料 + 检索条件
  -> 同空间的问题向量
  -> Qdrant 搜索及来源过滤
  -> 版本检查、证据过滤、上下文补全
  -> DeepSeek 基于证据回答
  -> 网页展示回答与引用
```

用户可以只检索而不生成回答。相似度用于排序，不是“答案正确概率”；超过阈值也不一定足够回答问题。

当前普通问答走固定路径：检索一次，再调用模型生成结构化回答。只有特定的结构化输出解析错误才尝试一次普通文本备用回答。这不是让模型无期限地决定下一步调用什么工具，也不是多 Agent 讨论。

`ResearchResponse` 定义回答、引用、状态和警告的结构。结构合法只是便于程序处理；它不能证明模型没有歪曲证据。普通路径的引用主要由提示词约束，不具备新对照流程同等强度的逐项编号门控，应结合展示的原文检查。

当模型不可用时，本地检索仍可单独使用；部分错误会显示降级结果或可读错误，不能保证任意故障都能生成自然语言答案。没有可靠证据时，应明确缺口，而不是补造一个看似完整的回答。

## 6. 新增的多文献对照如何工作

### 6.1 为什么需要分工

把多篇论文放进同一次全局 Top-K 检索，可能导致某一篇占满上下文。一个长提示词也难以清楚区分“本文说了什么”和“跨文献比较后能得出什么”。

新流程先逐篇取证，再分别分析。每个单篇分析员只看到自己的文献；综合员获得各篇有效分析和对应原文；复核员重新对照证据检查候选比较。

```text
按篇取证
  -> A 分析员 ─┐
  -> B 分析员 ─┼-> 综合员 -> 复核员（仅一轮）-> 比较结果
  -> C 分析员 ─┤
  -> D 分析员 ─┘
```

每篇分析包括主张、证据编号和当前未覆盖的维度。综合输出区分共识、差异与不可比，不应在研究对象或指标不一致时简单宣布哪篇“更好”。“没有检索到相关内容”不能推导为“论文没有研究这个问题”。

### 6.2 这里学到的 Agent 知识

LangGraph 的 Send 将不同文献分给同一种分析角色；异步模型请求真正并行；reducer 合并结果；汇合后进入综合和复核。这对应任务分解、上下文隔离、并行扇出与汇合、结构化交接和有限反思。

所有角色可以使用同一个 DeepSeek 模型。角色不同体现在职责和上下文，不要求每个角色部署不同模型。复核是独立的一次调用，但仍可能和分析员犯相似错误，不能用“多个 Agent 一致同意”代替科学验证。

这是一种由程序编排的有界多 Agent 工作流，不是自主智能体无限循环。检索、文件版本检查和结果保存属于确定性程序节点；有节点不代表该节点就是 Agent。

### 6.3 如何避免比较和引用失控

程序给本轮证据分配引用编号，模型只能引用已有编号。单篇主张不允许串用别篇证据；比较至少关联两篇有文字证据的文献。来源与页码从本地快照回填，不让模型随意编造。

复核员逐项判断 supported、uncertain 或 unsupported。只有恰好得到一次 supported 的比较进入主要结果表；漏审、重复审查、拒绝和不确定项进入待核实区。复核失败时，不把候选比较冒充通过。

单篇分析仍以 AI 草稿单独展示。检索片段不足时保留缺口；某篇失败不会清空其他篇的结果；不足两篇有效分析时不强行生成跨文献结论。

### 6.4 时间、费用与恢复边界

每次选 2–4 篇，最多四篇并行分析，加一次综合和一次复核，生成调用最多 N+2 次，即最多 6 次；每次输出最多 2600 token。没有自动重试或复核后再次修稿的模型循环。检索嵌入请求不计入这个生成调用数。

每篇取证 1–8 条、默认 5 条，文字上下文最多 6000 字符；取证等待上限 45 秒，生成调用外层 35 秒，整轮 180 秒。现有模型连接配置可能更早超时。

网页可以停止并恢复查看历史。停止阻止后续调用，但不能撤销已经被模型服务接收的收费请求；同步检索线程也不能被强制杀死，会等待收尾并阻止堆积新取证任务。

本地 SQLite 保存问题、证据快照、已完成草稿、阶段和结果。刷新网页不重跑模型；服务重启后未完成任务标记为中断，不自动继续付费推理。这里保存的是业务记录，不是可从任意节点恢复的 LangGraph checkpoint。

## 7. 图片和表格目前到哪一步

图片已经进入统一检索空间，因此文字问题可以找到相关图。网页也能展示图像证据。但当前 DeepSeek 回答路径不接收图片像素，多文献对照同样如此。

这意味着“找到了 Figure 2”与“正确读懂 Figure 2 的曲线、箭头和数字”是两件事。自动转写曾出现结构和数值错误，因此默认路径隔离未核验的图片转写，不把它当成确定事实。下一步若要真正图文推理，需要显式给视觉语言模型发送图像，并设计图值和结构核验，不能只换一个检索模型就算完成。

表格有独立的结构化单元格存储和只读 SQL 入口，不再只有 HTML 或截图。它便于查行列、定位数字、筛选和统计，但提取本身仍可能有合并表头、单位和跨页问题。新对照流程没有让 Agent 自动执行 SQL 计算，涉及精确数值时仍需回看原表。

## 8. 如何判断系统有没有变好

`/lab` 将检索实验与日常问答分开。评测集包含问题类型、期望证据和页面定位，分别观察文字、图片和混合查询表现。

Recall@K 检查期望证据是否进入前 K；MRR 检查第一条相关证据排得多靠前；页码召回检查是否定位到预期页面。证据 ID 命中和完整上下文命中还应分别看：找到某个短块不代表论证完整，找到等价证据也不一定命中预设 ID。

AI 辅助相关性判断与人工评分分开保存，AI 结果不能自动升级为人工金标准。重点异常可供少量抽查，不需要为每一次日常提问都人工打分。曾用于调参的开发集不能冒充独立测试集。

当前仍存在无答案问题返回相似证据、部分混合问题证据不完整、图表值未经核验等问题。新增多 Agent 不能修好上游根本没有找到的证据；一个流程测试通过也不等于科研比较质量已经达标。

## 9. 数据分别保存在哪里

| 位置 | 保存内容 |
| --- | --- |
| `library/` | 用户文献原件 |
| `.cache/mineru/` | 精析内容、布局、图片等缓存 |
| `.data/evidence.sqlite3` | 规范化文字/图片证据、来源及激活版本 |
| Qdrant 当前统一 collection | 文字和图片联合检索所用的向量及过滤字段 |
| `.data/tables.sqlite3` | 表格及结构化单元格 |
| `.data/evaluations.sqlite3` | 评测运行、证据快照及审阅记录 |
| `.data/comparisons.sqlite3` | 新多文献对照的阶段、证据和结果 |
| `.data/projects.sqlite3` | 旧研究项目、任务、草案和活动记录 |
| `.data/project_checkpoints.sqlite3` | 旧计划工作流的暂停与恢复状态 |

删除一个数据库不等于只清除缓存，可能丢失用户历史或业务状态。备份需要区分原件、派生产物和不可轻易重建的审阅/对照记录。上述数据库可能包含文献内容，虽然已在 Git 排除范围内，也不应公开上传。

## 10. 本机、远程 GPU 和外部 API 的边界

本机运行网页后端、SQLite 与 Docker 中的 Qdrant，保存资料及解析产物。主要本地入口分别是网页 8765、Qdrant 6333、MinerU 隧道 30000、Qwen 嵌入隧道 30001。

远程 GPU 服务负责 MinerU 解析与 Qwen 嵌入，因此精析会把 PDF 发到配置的研究服务器，嵌入会把相应文字或图片发送过去。这与发送到 DeepSeek 是不同的数据流，不能把“未勾选回答外发许可”理解为“所有处理绝不离开本机”。

只有确认外发许可才调用 DeepSeek 生成；对照会发送问题、所选证据以及分析稿，不读取研究计划中的项目记忆。密钥由本地环境配置提供，不写进文献、笔记或报告。LangSmith 的追踪与基础模型推理是不同服务，当前默认关闭追踪，不能把它的 API Key 当成模型额度。

当前应用面向本机单用户，只监听回环地址，没有公网用户认证、租户隔离或分布式任务调度。不能直接开放端口当成多人科研平台。

## 11. 原研究计划模块如何处理

已有模块保存研究目标、约束、任务进度与记忆，并通过 LangGraph 草案、规则检查、人工批准、应用步骤管理新增任务。它使用真正的 SQLite checkpoint 和 interrupt/resume，批准前不会把建议变成正式任务。

本次不删除或重构这些内容，但它不是当前工作的主线。多文献对照不会新增研究计划、修改已有任务或执行实验；只复用文件版本检查等已有基础能力。

## 13. 当前验收结论

新对照模块有 17 项专项离线测试，全套 96 项回归通过，覆盖真实 LangGraph 并行、证据隔离、调用预算、取消、超时、部分失败、幂等、权限和重启状态。浏览器通过临时资料与模拟模型验证整轮对照、结果分层和引用展开，桌面与手机布局已检查。

这些验证证明的是程序行为，不是实际科研结论准确率。当前还没有针对新流程调用真实 DeepSeek 做质量验收，也没有改变原评测金标准、人工评分或文献向量。后续应选择少量熟悉的论文和有明确依据的比较问题，检查证据覆盖、可比性判断与复核是否有效，再决定扩展规模。

当前项目的准确定位是：**可以管理文献、追踪证据、辅助问答并进行有界多 Agent 对照的个人科研助手；不是无需核验的自动科学家。**

## 14. 从项目使用到工程能力

新增本地执行轨迹模块 `research_assistant/core/agent_telemetry.py`，当前覆盖多文献对照，不扩展研究计划。每轮保存 Trace；取证、分析、综合和复核阶段有 Span，各模型调用作为子 Span。通过单调时钟记录排队时间、请求时间和整轮时间；请求时间包含网络、供应商等待与生成，不等于纯 GPU 推理。

结构化模型调用使用 include_raw=True，先提取服务返回的用量，再处理解析结果。因此输出格式失败仍可保留已报告用量。日志只保存白名单计数、角色槽位、时间、错误类别和 prompt/schema 指纹，不复制文献原文、提示词或异常全文。业务结果库原来保存的证据快照仍存在，这并不意味着整个数据库不含文献内容。

用量缺失、格式不一致或取消无响应时记录未知；缓存输入在 LangChain 口径下已含在 input_tokens，不能再加一遍。不使用字符数估算 token，不按不完整用量计算费用。旧记录不补造轨迹，重启保留不完整计时状态。

并行实验使用相同合成问题、证据、角色和固定延迟，只改变并发数 1/4。三次模拟耗时中位数为 724.298/294.615 ms，两边均 6 次调用；这验证异步编排而非真实业务提速或答案质量。固定证据生成实验与已有检索 Recall/MRR 评测是不同层次，不能相互替代。

本阶段的学习材料见 `学习笔记/01_Agent可观测性与并行实验.md`，包括来自公开源码的两个具体例子和用户练习。岗位对齐路线将工程闭环、会话记忆、图文推理、质量消融、可复现交付和可选研究实验分开；不把项目已实现当成用户已经掌握。
