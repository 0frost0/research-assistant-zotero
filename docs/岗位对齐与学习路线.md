# 科研助手：岗位对齐与学习路线

依据：用户提供的四张招聘截图，整理于 2026-09-07。它们是能力目标的样本，不代表完整招聘标准或录用承诺。本文件不编造学历、经历、论文或实验结果。

## 1. 先确定主线

当前最匹配的是 AI 工程师 / Agent 应用开发方向：它强调需求落地、RAG、工具编排、记忆、可观测性、自动评测、异步和降级。科研助手已经具备相关基础，适合继续打磨成可以展示、测量和解释的项目。

多模态算法方向还要求多模态任务能力、可能涉及图像生成、视觉理解或模型训练。当前 Qwen 是嵌入模型，接入 MinerU 是解析能力，不能据此宣称已经掌握 Diffusion 或多模态模型训练。

Agent Memory Research 更偏研究：记忆策略、长时交互、上下文工程、实验设计，以及 PyTorch、LLM 训练/微调或强化学习基础。数据库持久化与 checkpoint 只是工程状态保存，不能当成记忆算法创新。这个方向作为后续研究分支，而不是给当前项目加上 Memory 标签就算匹配。

截图还包含学历、出勤、实习时长等条件，这些不能靠项目补齐。是否符合需要用户依据自身情况单独确认。

## 2. 当前项目证据与差距

| 招聘要求 | 已有可核验内容 | 仍缺什么 |
| --- | --- | --- |
| RAG / Context Engineering | 统一嵌入、出处版本校验、上下文补全、检索评测 | 独立留出集、答案级正确性与拒答校准 |
| Agent 编排 | LangGraph 按篇并行、综合、有限复核、预算 | 单 Agent / 多 Agent / 有无复核的真实质量与成本对照 |
| 可观测与归因 | 本轮增加角色与阶段 Span、计时、用量和错误分类 | 普通问答链路尚未接入同等级轨迹；真实流量分布尚未采集 |
| 性能与稳定性 | 超时、取消、部分失败、重复请求保护、离线回归 | 多用户队列、负载测试、资源容量和运行告警 |
| 多模态能力 | Qwen 统一图文嵌入、MinerU、原图与表格证据 | 最终模型看图推理、图值/结构准确性实验 |
| 长期记忆 | 旧计划模块有显式状态及 checkpoint | 文献问答会话记忆、读写策略、冲突/遗忘/污染控制、记忆评测 |
| PyTorch / 微调 / RL | 尚无本项目可证明的训练成果 | 自行实现和理解实验，不能把调用 API 写成训练 |
| 独立工程能力 | 真实可运行项目和故障笔记 | 用户能独立解释、定位问题并提交自己的改动；目前未验收 |

## 3. 每阶段如何一起推进

每阶段按“真实问题 -> 原理 -> 关键代码 -> 控制变量实验 -> 用户小改动 -> 复盘”执行。讲解围绕运行时数据与控制流，不逐行翻译全部代码。用户的小改动不由助手预先代做；遇到困难可以逐步提示。

维护两种状态：**项目功能是否完成**，以及**用户是否能解释和修改**。前者有测试也不意味着后者已经通过。不会一次自动塞入数个大型模块，使项目代码超过可掌握范围。

## 4. 分阶段路线与验收

### 阶段 A：把执行过程变得可测量（当前阶段）

功能：多文献对照增加本地调用轨迹，区分阶段耗时、并发等待、模型请求耗时、用量缺失、解析错误与连接错误；提供固定证据的串行/并行实验。

实验：相同问题和证据、同样角色、相同调用次数，只改变并发数 1 与 4；记录数据/提示词指纹、依赖版本、失败样本和计时分布。模拟数据仅验证程序调度，不用来声称真实业务提速。

用户任务：先解释“为何并行不降低调用次数”，再在实验脚本增加并发数 2 的对照组，保留原始记录。完成改动后由助手检查指标口径和测试，不修改生产默认并发数。

状态：项目实现本轮交付；个人掌握程度待用户练习验收。

### 阶段 B：文献问答的会话记忆与上下文策略

功能：先建立带来源约束的多轮会话，区分最近消息、会话摘要和用户明确保存的偏好。问题改写用于消除“它/这篇”的歧义；每次仍重新检索，历史模型答案不升级为事实证据。

设计重点：何时读、何时写、谁允许写、冲突怎样处理、能否删除；资料切换后旧文献结论不能污染新答案。先做规则基线，再考虑 LLM 提取记忆。研究计划模块仍暂缓重构。

实验：无历史、滑动窗口、摘要 + 最近消息三个基线，比较指代消解成功、过期信息、跨会话隔离、输入 token、延迟。采用按主题拆分的测试样例，包含更正旧偏好和删除记忆后的问题。

用户任务：实现一个“用户更正偏好时更新旧记忆而不是追加矛盾条目”的小功能，并写回归测试。验收时必须解释 checkpoint、聊天记录、可检索记忆的不同。

状态：未实施，不宣称已有长期记忆算法。

### 阶段 C：真正的图文证据推理与表格工具

功能：将已定位原图在用户授权后交给视觉语言模型，并保留页码/图号；增加确定性表格查询工具与数值来源。根据问题选择文字、图像或表格路径，不能全交给模型猜测。

实验：文字上下文、原图 + 正文、结构化表格三种输入对照；分别测图中数值、坐标轴、拓扑关系、单位和来源定位。至少保留图像不可读、单位缺失、跨页表头等失败案例。

用户任务：给一个表格查询工具增加单位检查与错误返回，说明为什么只读权限比简单 SQL 正则更重要。模型服务、GPU 和外发成本在实施前明确。

状态：未实施，不把图像检索包装成视觉推理。

### 阶段 D：证明 Agent 分工有没有价值

功能：保留单模型直接综合基线，对照多 Agent 无复核与有复核策略；版本化 prompt、输入证据和结果，避免事后改标准答案迎合结果。

实验：用一组熟悉论文开发，再用未参与调参的新论文留出验证。分开报告正确性、引用支持、可比性、拒答、token、延迟与复核误删；人工抽查只集中在固定评测与异常，不要求每次日常问答评分。

用户任务：找到一条“复核把正确结论删掉”的案例，解释召回与保守性之间的取舍，提出并验证一个改进。最终报告包括负结果，而不是只挑优秀截图。

状态：尚未真实质量验收；阶段 A 的并行实验不能代替本阶段。

### 阶段 E：工程交付与可展示材料

功能：依赖可复现、CI 离线回归、容器/服务边界清晰、健康检查、公开用合成示例数据；针对单用户瓶颈设计队列与资源限额，再决定是否实现多用户。

产物：干净的公开演示配置、架构介绍、可复现实验、失败复盘和 5 分钟演示。不得将真实文献原件、未授权数据、密钥或本地数据库公开推送。

用户任务：从新环境启动合成演示，独立排查一次连接故障；能指出问题位于隧道、嵌入服务、Qdrant 还是生成模型。准备公开仓库或部署时另行确认数据与许可证。

状态：待实施；本轮不会自动创建公开仓库或提交招聘申请。

### 阶段 F：研究型岗位的选做分支

只有前面可测量、可解释后才扩展。Memory 方向可研究规则读写与模型策略、记忆压缩、冲突和长期记忆评测；多模态方向可研究检索困难负例、图文对齐或小规模微调。训练实验要明确任务、数据许可、基线、训练/验证划分、GPU 预算和统计口径。

不默认训练大模型，不预先承诺论文或性能提升，不因为使用了 LoRA 就声称完成算法研究。PyTorch、梯度、损失函数、优化器和评测泄漏等基础需要用户实际理解；Agentic RL 等方向不作为当前工程项目的装饰项。

## 5. 什么时候可以准备面试

以下是项目准备度检查，不是录用判定：

1. 不看长文档，能在 5 分钟讲清 PDF 到答案的数据流和信任边界。
2. 能解释为什么图文共用嵌入空间，为什么这仍不保证检索正确。
3. 能根据一条轨迹判断瓶颈，并区分请求失败、输出解析失败和证据不足。
4. 能独立完成一个有测试的小修改，而不只是运行助手给的命令。
5. 能重跑对照实验，解释控制变量、统计口径和结果适用范围。
6. 能讲一个失败案例、一个没有取得提升的实验，以及如何决定下一步。
7. 能明确自己做了哪些设计、实现和实验，哪些部分借助了 AI；不把生成代码冒充完全独立开发。

目前不根据已有聊天记录判断用户已通过以上项目。后续逐项演示与问答后再更新。

## 6. 简历如何保持可信

现阶段可作为待核实草案：

> 科研文献助手（个人学习项目，使用 AI 辅助开发）：集成 MinerU、统一多模态嵌入与 Qdrant 构建有来源的文献检索；以 LangGraph 实现按篇并行分析、综合和有界复核，提供引用校验、超时取消与本地运行记录，并建立离线回归和串行/并行实验工具。

这段描述须在用户能解释相应实现后再采用。后续实验有真实数据、可复现报告和清晰个人贡献后，才能增加量化成果。当前模拟耗时、测试用例通过率、AI 复核通过率都不能写成真实答案准确率或业务提效比例。
