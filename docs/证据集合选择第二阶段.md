## 方法与关键取舍

- 输入：问题、已选原文集合、新候选；输出：该候选是否补充未覆盖的信息需求。先选至多 6 条／12,000 字符，不用未经校准的概率阈值证明“充分”。候选缺失无法由选择器补回。
- 基础模型：`Qwen/Qwen3-Reranker-0.6B`，revision `e61197ed45024b0ed8a2d74b80b4d909f1255473`，Apache-2.0。复用官方 yes/no logits 和格式，训练二分类交叉熵；不是生成答案，也不是复现 SetR。
- LoRA：只更新 `q_proj/v_proj`，rank 8、alpha 16、dropout 0.05；AdamW、梯度裁剪 1、seed `20261110`。小适配器与第一阶段权重分离，不改正在使用的服务。
- 采用左 padding／最后有效 token 的二分类 logits，训练和集合选择共用 prompt。**不截断**：训练整条排除超预算样本并计数，离线推理超长则失败；标注维度、来源 ID、标签不进入 prompt。
- 专用远端 `.selector_env` 只读复用项目 `.gpu_env`，额外固定 `peft==0.17.1 / accelerate==1.10.1`；不在生产环境安装训练依赖。训练预算显式限定 steps／epochs／单步输入长度和时间（在步间检查，不是硬实时抢占）。

## 数据：不能把主题分类当成覆盖标注

schema 为 `evidence-selector-v1`：每题 `dimensions` 包含**问题特定信息需求**的 ID、描述和类别；候选 `covers` 给出已核对的需求 ID，空数组表示已核对无增益，`null` 表示未知。由已选集合的 coverage 并集自动推导新候选的 `added_dimensions` 和二元标签。

例如“方法、适用人群、结果、局限”是四个需求；两个都属 result 的不同数值也可拆成两个需求。一个候选可覆盖多个需求；同一事实的改写在空集合时是正例，在该事实已覆盖时是负例。不能只为每段加一个 `method/result` 分类，然后声称学到了互补性。

**现有 52 case 不用于正式 LoRA 训练。** 构建器只把 48 正例／57 个锚点导出成开发标注材料（75 个代理样本）；其他题的锚点不是已核对负例，仍为 `covers=null`。训练器和维度评测器都会拒绝该代理数据。锚点数不等于语义维度数。

纸面 train/dev/test 按来源论文分为 8／3／1 篇，仅用于开发隔离，**test 不是独立人工 gold**。校验范围包括所有候选／干扰段的论文、source ID 和归一化全文哈希，不能只检查问题的主论文。多论文题需先建立共享论文连通分量再分组，本轮尚未提供该自动切分器。近重复／同文不同版本还需人工或文档身份映射核查。
