# 中文论文阅读与可追溯记忆：设计和验收

日期：2026-09-09。此文说明本次实际代码、设计取舍和验证边界。操作入口见 README；不是用架构规划代替实现。

后续增加日常按需翻译入口：原文选区 → 侧栏中文 → 本地缓存/来源回跳 → AI 草稿 → 用户确认。它不重排 PDF；整篇翻译仍由独立后端执行，上传自动开关默认关闭（保留显式保存的偏好）。下面原有全文演示需用户主动开启或手动提交。新增 11 项确定性及 8 项模拟浏览器验证、费用边界详见 [按需翻译报告](Zotero按需翻译借鉴与实现.md)，不把模拟结果当作真实翻译质量。

## 1. 从真实仓库出发

首先核对了 `docs/项目介绍.md`、根目录 AGENTS.md 和相关实现。原项目是 Starlette + 原生 JavaScript，不是 React；原文在 library，MinerU 负责结构化提取，Qwen/Qdrant 负责原文检索。没有迁移前端，也没有引入新的多 Agent 系统。

| 原有能力 | 代码位置 | 本次衔接 |
| --- | --- | --- |
| 上传、删除与原文路径检查 | research_assistant/web/web_app.py：library_api、delete_library_file、safe_library_path | 上传后归档原件；删除检索资料之前先保留原件副本 |
| PDF/MinerU 解析 | research_assistant/ingestion/pdf_extractor.py、mineru_extractor.py | 沿用；翻译使用独立排版引擎，不把提取文本重新打印成 PDF |
| 原文证据、解析版本及 bbox | storage/evidence_store.py、retrieval/unified_index.py | 不改变已有证据 ID 或向量；MinerU bbox 不直接当阅读器选区 |
| 证据卡片与问答 | web/static/app.js、agents/research_agent.py | 增加阅读入口和带入摘录；阅读工作台有独立双来源问答 |
| 模型配置 | agents/research_agent.py：build_chat_model | AI 草稿/回答复用；手动笔记完全不依赖模型 |
| 测试 | tests/ 原有 113 项回归 | 新增 reading_memory 专项测试及可执行浏览器/真实模型验收脚本 |

新增模块是 `memory/`（业务事实）、`translation/`（队列与适配）、`web/reading_api.py`（接口）及 `web/static/reader/`（阅读交互）。原 `/api/run` 仍执行原文问答；需要结合个人记录时使用 `/reader` 的问答区域。这里采用一次检索、最多一次生成的确定性工作流，没有让模型自行决定写入记忆。

## 2. 文件身份与数据库

`library/` 是当前参加检索的资料集合。新阅读模块另外保存不可覆盖的 `.data/reading_artifacts/<sha256>.pdf`。同一原件哈希对应一个阅读 paper_id；每个译文版本有独立 artifact_id，指向原件 parent_id。即使两次输出字节相同，重新翻译也能保留独立产物身份。

阅读 paper_id 与旧证据库按来源路径派生的 document_id 是不同命名空间，不能直接互换。通过 source 文件名衔接旧检索时，会先核对当前文件 SHA256 与阅读原件一致；同名替换或从检索库移除后，不拿新文件替代旧原件。旧笔记仍能访问保留的文件。相同内容改名的别名管理暂未扩展。

SQLite 是事实来源：`.data/reading.sqlite3`。`ReadingStore.__init__` 在事务内执行幂等的增量建表，PRAGMA user_version=1；遇到更高版本拒绝写入。没有改动旧证据、评测或项目数据库。

| 表 | 用途 |
| --- | --- |
| papers、artifacts | 原件、派生版本、哈希、页面几何、生成配置及校验记录 |
| annotations | 可独立保存的高亮/下划线、产物锚点及多行矩形 |
| notes | 当前 revision 指针 |
| note_revisions | 正文、类型、来源、确认/归档状态、来源锚点、前一版本及时间 |
| reading_settings | 自动翻译开关 |
| translation_jobs | 缓存键、排队/运行/成功/失败、真实阶段、重试次数及错误 |
| selection_translation_schema | 选区模块独立的增量迁移版本，当前为 1 |
| selection_translations | 选区请求、原文锚点、机器译文、缓存身份、已报告用量及未知用量预留 |

选区翻译先在 SQLite 事务内预留次数/用量，再调用模型；重启将 pending 标为 interrupted，不自动重发。机器译文独立存储；转成草稿时 revision 保存 generation_source，后续编辑保留来源，未确认不进入正式笔记检索。新增表不覆盖旧笔记、产物或任务。

每次编辑通过 BEGIN IMMEDIATE + expected_revision + 条件 UPDATE 原子追加新 revision。旧 revision 的 UPDATE/DELETE 由 SQLite trigger 拒绝。指针变动与插入 revision 同一事务提交，插入失败则整体回滚。多窗口冲突返回 HTTP 409，前端保留输入，允许先看最新正文再明确合并。历史链接打开只读版本。

业务方法校验论文、批注和锚点归属；本版未用 SQL 外键覆盖所有 JSON 内嵌关联，不能绕过业务接口任意修改数据库。单用户、单 Web 进程运行；多 worker 队列所有权和多用户权限不在此版范围。

备份时停止应用，把 reading.sqlite3 和整个 reading_artifacts 一起备份；仅备份数据库无法恢复原 PDF。译文和旧 revision 不做自动回收。translation_work 是可重建工作目录，不是笔记事实来源。恢复后原件哈希仍要一致。

## 3. 为什么坐标属于文档版本

前端使用本地固定版本 PDF.js 5.4.149 的 canvas + TextLayer。浏览器选区先与每个文本节点求交集，再通过 viewport.convertToPdfPoint 转换为 PDF user space。中文译文可能每个字都是一个文本节点，所以先合并同一行相邻字形，再识别真实栏间空隙。不能把任意两个相距较远的汉字当成跨栏。

锚点保存 artifact_id、artifact_hash、物理页码（从 1 开始）、coordinate_system、view_box、rotation、UserUnit、rects[]、摘录及可选 evidence_id。view_box 采用 MediaBox/CropBox 交集；重绘从这些 PDF 坐标换算到当前 viewport，随缩放、窗口和旋转恢复。下划线方向也跟随页面旋转。

跨页、跨窗口和跨栏/不连续选区明确拒绝，提示拆开保存；不画覆盖整栏空白的大矩形。任意角度的倾斜文字、复杂竖排和超过 200 个原始文本片段的选区没有完整支持，不能视为所有 PDF 的通用标注引擎。

来源有四个边界：论文原文、机器译文、用户记录、未确认 AI 草稿。译文选区固定绑定当次产物，不复用原文 bbox，不按页数相同推断映射。映射默认 unaligned；原文直接选区为 exact（仅指位置锚定），证据卡片摘录没有验证坐标时为 page_only。exact 不表示模型结论正确，也不表示译文与原文语义一致。

用户可在译文笔记中切换原文、补选原文选区并“加入笔记来源”。这是独立的人工补选锚点，不自动把两个摘录宣称为精确翻译对应。旧译文与原件长期保留，因此重新翻译不迁移或损坏旧划线。新版对照可同步物理页码（页数不同禁用），也可关闭；不声称段落精确对应或自动联动滚动位置。

## 4. 翻译后端与任务生命周期

选型与许可证细节见 [翻译引擎与许可证](翻译引擎与许可证.md)。采用推荐的 `pdf2zh_next.high_level.do_translate_async_stream`，未直接依赖 BabelDOC 的内部高层 API。引擎在单独 Python 环境运行；主应用不升级 PyMuPDF/科学计算依赖。

固定组合：pdf2zh-next 2.9.0、BabelDOC 0.6.2、PyMuPDF 1.25.2。完整 Windows/Python 3.11 解析依赖记录在 deployment/translation/requirements-lock.txt。目标中文、表格文字翻译、关闭自动术语提取。初版并发和 QPS 均为 1；adapter v2 调整为并发 4、QPS 2，对 DeepSeek V4 显式禁用思考，并增加余额预检和有限重试。实际提速因账户余额不足尚未复验，详见 [翻译故障与性能修复](翻译故障与性能修复.md)。没有自研 PDF 翻译排版引擎。

PDF 上传完成后保存原件并识别语言；配置可用且自动开关开启时，英文新上传进入队列。中文不再翻译；混合/未知允许手动确认。低文字页（每页少于 40 字符）这里只作为保守的不自动翻译规则，不是 OCR 调度器，也不是扫描识别的充分条件；纯图页会误拦截，原文仍可读。语言规则是简单字符统计，有误判可能。

缓存键包含原件哈希、目标/源语言、引擎版本、模型、端点哈希、适配器版本及影响输出的固定设置。密钥不进入任务 JSON、命令行和应用日志，通过 stdin 传给 worker。默认重复提交复用任务；失败可手动重试；明确生成新版本加入 generation 标识，保留旧产物。更改配置后，手动重试按新缓存键建立或复用任务，不覆盖旧配置记录。

队列单任务运行；进度来自引擎 overall_progress，启动下载与校验阶段没有百分比则显示阶段。超时默认 1800 秒，取消/停止时结束进程树；重启把遗留 queued/running 标为失败，提示手动重试，不长期显示运行中，也不自动重新计费。

成功产物检查页数、页面几何、可选中文、低文字页、完全未变化页、乱码和数字集合。真实论文测试后增加长段未变化英文检查，拦截只翻译部分正文的明显失败；短段漏译仍可能漏检，长英文引用可能误触发。数字缺失记录 warning，需排除文字提取器拆字造成的误报。未通过检查的文件不进入可读译文列表。生成成功只代表自动检查通过，human_review=pending，不等于已证明全文语义完整、公式正确、复杂表格不变形。原文—译文段落映射没有稳定契约，因此不使用未经验证的映射。

上游退出日志可能包含单独的数字，JSON 解码成功也不代表是进度事件。适配层只接受字典及白名单 type；这个边界已由真实队列失败和重试验证。

## 5. 笔记检索和回答边界

正文类型为理解、疑问或想法。每条新笔记需至少一个来源锚点；高亮可独立保存。AI 接口只能新建未确认草稿，显式用户确认追加新 revision，author_source=ai_assisted 仍保留。问答流程没有保存、确认或归档工具。

笔记检索采用中文字符 2/3-gram 与英文词的轻量词面重叠排序，不依赖嵌入或模型连接。默认仅检索当前、已确认、未归档的记录。每次先读取数据库当前版本，缓存只存 token 集合且以 note_id/revision 标识；缓存失败重算，提交事务后的失效失败不丢笔记。返回候选前及模型回答完成后再次核对版本，变化则丢弃旧回答并要求重问。

原文检索和个人笔记是两个独立结果列表，不把笔记或译文写入旧向量集合。问答响应分别返回 original_answer/original_citations 和 notes_answer/note_citations；笔记引用附 note_id、revision、链接，点击回到相应产物和选区。模型输出的 ref 必须来自候选列表，程序回填来源，不信任模型自造位置。

模型断网或引用格式不合格时显示本地检索结果；这不等于已经生成科研答案。原文服务失败时，不以个人观点替代原文。结构化引用合法也不证明语义忠实，仍需要核对模型归纳；本版没有宣称自动解决所有观点冲突。

## 6. 实际验证结果及局限

确定性测试见 tests/test_reading_memory.py：覆盖创建、追加历史、归档、并发 CAS、插入失败回滚、不可覆盖 revision、草稿隔离、缓存故障、译文版本保留、源文件哈希、几何校验、断网、生成期间版本变化、任务去重/中断/超时/重试和非协议日志。完整测试数量见最终 README 验收记录。

真实翻译与模拟验证分开：

| 验证 | 实际结果 |
| --- | --- |
| 合成双栏科研 PDF，含正文、公式、数值、表格、折线图、引用 | 真实模型 + 固定翻译引擎生成 2 页中文 PDF；逐页渲染检查、文字可提取、几何及数字集合检查通过 |
| 持久化后台队列真实运行 | 首次发现退出日志误判；修复后同任务重试成功，约 120.67 秒，阶段采样的进程树 RSS 峰值约 2561.9 MiB（含共享页重复计数，非最低内存需求；含已有缓存） |
| 译文质量缺陷 | 段落换行/留白改变；表格列间距压缩；同一术语不同位置翻译不一致。标题、图位置与样本公式保留，不代表所有复杂公式通过 |

| MDAgent 真实论文节选 | 用户明确授权前两页至 api.deepseek.com 后执行；901.459 秒生成，逐页质量验收失败：摘要全英文、作者/脚注排版异常。修复长段未译原文拦截后，本样本拒绝发布为完整译文；见 [两页详细报告](MDAgent两页翻译验收.md) |

浏览器使用 8766 隔离数据和真实引擎译文：原文多行划线、刷新、放大、窗口变化、旋转、中文正文真实鼠标多行拖选、笔记编辑/历史/冲突、问答引用跳回均已执行。原生旋转 90°、CropBox 偏移、UserUnit=2 的样本也验证了位置，选区与标记最大边界误差实测 0.0078125 CSS px。更多浏览器、移动端触摸选择和复杂倾斜排版尚未验收。

脚本和产物：scripts/reading_sample.py、reading_live_check.py、reading_preview.py、reading_browser_check.js、reading_browser_extra.js；本地截图 output/playwright/；真实结果 output/reading-live/report.json。合成样本为自建 CC0 测试内容，不能包装成真实科研效果。

## 7. 五分钟演示

复现浏览器测试时，运行 `scripts/reading_preview.py --run demo01` 创建独立验收数据（名称仅字母数字下划线连字符）。先用 CLI 打开 8766/reader 并获取快照，再按 `reading_browser_check.js`、`reading_browser_extra.js`、重启同一 `--run` 服务、`reading_browser_restart.js` 的顺序执行。调用方式：`npx --yes --package @playwright/cli playwright-cli -s=reading run-code --filename scripts/脚本名.js`。新一轮改用新名称即可，不必删除旧数据。

最终验收补充：最初全套 136 项 Python 测试、3 项 JavaScript 几何检查通过；真实论文漏译修复新增 3 项测试后，全套 139 项 Python 回归通过。实际重启后原文划线和中文笔记 revision 恢复；补选原文保持译文未对齐；归档后默认问答不召回，历史仍可返回旧产物。停止脚本核对 PID 身份后终止整个应用进程树。浏览器脚本按顺序在 8766 隔离数据执行，重复执行会追加测试记录，不能对正式站点执行。本次漏译修复未改前端，未重复浏览器全流程。

1. 0:00–0:40：在主页或阅读器上传有文字层英文 PDF，展示原件保留、语言识别和翻译排队。若示范时间受限，用已完成的样本展示产物，并如实说明之前等待的时间。
2. 0:40–1:30：打开中文译文，下载并选择文字；切换中英对照，说明两窗独立、译文未对齐和表格需要核对。
3. 1:30–2:20：中文段落划线，写下自己的理解，保存 revision 1；切到原文补选来源并追加版本。说明原文事实与个人观点的区别。
4. 2:20–3:10：重启网页服务，打开同一笔记，验证旧产物/划线恢复；调整缩放，查看历史。
5. 3:10–4:10：修改笔记，询问“我对这个方法还有什么疑问”，看到最新 revision 和正文；原文问题切换为“原文”，不拿笔记代替事实。
6. 4:10–5:00：点击问答引用回到 PDF 选区；两个窗口制造版本冲突，显示未保存输入仍在。最后展示确定性测试、中文失败案例和真实翻译缺陷，而不是只展示成功页面。

求职时可解释的设计取舍是：可验证来源身份、不可覆盖的版本、读写权限边界、外部工具协议隔离和离线降级。它们解决长期阅读记录的可靠性问题，并不需要堆叠额外 Agent。
