# 翻译引擎选型、固定版本与许可证

核实日期：2026-09-09。

## 接口与版本

用户提供的 PDFMathTranslate-next 仓库已迁到 [PDFMathTranslate-next/PDFMathTranslate-next](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next)。核实到发行版 2.9.0；BabelDOC 最新发行版为 0.6.4，但不能直接把这两个最新版一起安装：前者要求 PyMuPDF<1.25.3，BabelDOC 0.6.4 要求 PyMuPDF>=1.26.7。

本项目使用 pdf2zh-next==2.9.0、BabelDOC==0.6.2、PyMuPDF==1.25.2，pip check 通过。顶层选择见 deployment/translation/requirements.txt；完整解析依赖见 requirements-lock.txt。依赖没有用 --no-deps 强行绕过冲突，也没有污染已有 deepagents 环境。

依据：

- [PDFMathTranslate-next 2.9.0 Python API](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/v2.9.0/docs/en/advanced/API/python.md)
- [PDFMathTranslate-next 2.9.0 依赖](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/blob/v2.9.0/pyproject.toml)
- [BabelDOC 仓库及接口说明](https://github.com/funstory-ai/BabelDOC)
- [BabelDOC 0.6.4 依赖](https://github.com/funstory-ai/BabelDOC/blob/v0.6.4/pyproject.toml)
- [BabelDOC 0.6.2 依赖](https://github.com/funstory-ai/BabelDOC/blob/v0.6.2/pyproject.toml)

BabelDOC 自述其直接 API 为内部接口，推荐通过 PDFMathTranslate-next 的 do_translate_async_stream 使用。因此适配器只依赖该推荐流式入口。SettingsModel 固定语言、并发和输出配置；finish.translate_result 是对象，不能当作字典读取。没有假设其提供稳定的原译文段落映射。

后续 adapter v2 增加 `deployment/translation/bounded_client.py`：上游没有公开重试次数设置，因此在独立进程内包装固定版本 OpenAITranslator 的请求方法，移除 100 次限流重试和 SDK 叠加重试，保留上游提示词/缓存/计数。此处属于依赖内部结构的兼容层，升级版本须跑专项测试；没有修改 site-packages，不代表免除 AGPL 义务。详见 [故障与性能修复](翻译故障与性能修复.md)。

## 运行环境和资源

上游要求 Python >=3.10,<3.14，本机验证 Python 3.11 + Windows。PDF.js 5.4.149 通过 npm 安装并本地托管；前端无需 React 或 CDN。现代 Chromium 已验收，旧浏览器未保证。

翻译文本交给配置的模型 API，布局分析使用本地 CPU/ONNX；无需为此部署本地生成模型 GPU。首次启动需联网获取布局模型和字体，耗时取决于缓存与网络。隔离 Python 环境本机实测约 1.06 GB 磁盘，另需模型/字体缓存、原件与各译文空间。两页合成样本队列重试实测约 121 秒，采样进程树 RSS 约 2.50 GiB；这是本样本观察值，不是最低硬件门槛或整篇论文承诺。长文献需更多时间/内存，模型调用计费另计，不能从页数准确推算 token 费用。

运行方式：主 Starlette 服务负责持久任务及进程生命周期，deployment/translation/worker.py 在 .translation_env 中调用上游；不是运行上游公网 Gradio。服务默认仅监听 127.0.0.1。Linux 部署需重建该平台环境并设置 RESEARCH_TRANSLATION_PYTHON；当前锁文件来自 Windows，不宣称 Linux 已验证。
