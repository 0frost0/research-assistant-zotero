# 个人文献记忆（方案 3）

## 已完成的基础闭环

- Zotero 检索结果可以直接“写入专题笔记”，自动带入论文来源标识、页码、摘录和 Zotero 跳转链接。
- 笔记继续使用 SQLite 的不可变 revision；编辑追加版本，旧版本可通过“历史”查看。
- 保存时保留 `confirmed`、`author_source`、`source_status`。未确认记录不进入默认笔记检索，归档记录也不默认召回。
- 编辑已归档记录时会保留归档状态；只有显式提交恢复操作才重新进入默认检索，避免部分客户端请求误恢复旧记忆。
- 来源锚点会单独记录摘录核验状态：原文页内能找到逐字摘录时标为已核对，否则用户记录仍可保存但显示待核对；AI 草稿仍拒绝未核验摘录。
- 旧版本笔记没有这些字段时，读取、检索和历史查看会按当前不可变 PDF 即时补算状态，不改写旧 revision，也不会要求重新导入论文。
- 多窗口编辑仍使用 `expected_revision`；冲突时不会覆盖当前输入。
- “仅笔记”问答新增独立路径，只读取当前有效个人记录；回答标记为“你的记录”，不把个人观点当作论文原文。
- “文献与笔记”现在由组合问答编排：论文原文和个人记录分别检索、分别生成、分别展示；原文最多一次回答加一次复核，笔记最多一次回答，合计预算可见。
- 笔记列表中的每个来源锚点都能回到 Zotero 页码；只有没有可用 Zotero 链接时才退化为页码和摘录提示，不伪造跳转。
- 个人记录回答中的引用也会列出记录 revision，并提供该记录关联的原文页码按钮；记录入口和原文入口分别处理。
- 论文原文、个人记录和 AI 草稿仍分开；系统不自动确认模型草稿。
- 原文问答结论可以点击“保存为 AI 草稿”。草稿保留原文摘录、页码和 Zotero 链接，默认未确认，不进入个人记录检索；用户核对后确认会追加 revision，仍保留 `author_source=ai` 和 `confirmed_by=user`，不会伪装成手写记录。
- AI 草稿保存前还会在 SQLite 中核对：来源 PDF 属于当前知识库、页码存在、摘录确实出现在该页（允许 PDF 换行差异）。任一条件不满足就拒绝保存，不生成无来源记忆。
- Zotero 原生笔记和批注同步后分别标记为 `external_note` / `external_annotation`，可以进入个人记录问答；结果保留 `author_source=external_zotero`、revision 和 `zotero://` 链接，仍不会进入论文原文证据路径。
- 异步问答任务写入独立的 `qa_jobs.sqlite3` 后，插件“问答历史”可以查看最近任务的状态和失败原因；成功任务可直接恢复已保存回答，不会重新调用模型或重复消耗额度。
- 个人记录初次词面门控全部过滤时，允许一次受限问题改写，再检索并回答；改写只产生检索词，不产生事实，整条路径最多 2 次模型调用，且仍只传入个人记录。
- Zotero 问答结果提供可选的“有帮助 / 部分有帮助 / 不可靠 / 正确拒答”反馈。反馈保存回答快照哈希、知识库 revision、引用和评分，作为未批准评测候选；不会修改笔记，也不会自动变成 gold。

## 使用方式

1. 在 Zotero 工作台检索，点击原文结果旁的“写入专题笔记”。
2. 确认来源摘录后填写“理解 / 疑问 / 想法”，保存。
3. 在“专题笔记”中编辑、查看历史或归档。
4. 将检索范围切换为“仅笔记”，询问“我之前如何理解这个方法”，结果会标明来自个人记录。

## 边界

- 没有关联来源的笔记仍可保存，但会显示“未关联来源”，不应当作论文证据。
- 笔记检索首版使用当前知识库的轻量检索；不是自动总结全部阅读历史。
- 模糊问题的改写是有界补救，不是无限自主循环；改写失败、没有不同检索词或二次检索仍无记录时，系统返回无答案并保留原因。
- 反馈不是每次问答的必填步骤；可只抽样确认，使用 `benchmarks/export_qa_feedback_candidates.py` 导出后再人工核对原文和 revision。导出文件标记为 `unapproved`，不能直接交给评测器。
- 组合回答不会把两类证据合成一条无来源结论；如果其中一侧没有记录、模型不可用或复核失败，另一侧仍会保留，并在对应分区显示缺口。
- 组合路径对单侧临时故障做隔离；只有 revision 冲突或请求取消会终止整轮，避免把旧结果继续展示。
- 组合路径在并行分支汇合前保存共同知识库快照，并在合并结果返回前再次检查 revision；期间论文或笔记发生变化时拒绝整轮旧结果，避免混合不同版本。

## 验证

`tests/test_knowledge.py` 覆盖来源锚点、revision 历史、归档、AI 草稿确认和历史 HTTP 接口；`tests/test_knowledge_qa.py` 覆盖插件笔记、Zotero 原生笔记/批注、组合问答的来源分区、HTTP 接口和评测 split 保护；隔离 Zotero fixture 还检查问答后保存 AI 草稿、用户确认、两类分区标题及原文跳转。可用 `benchmarks/evaluate_personal_memory.py` 对固定的中文问题集计算 Recall@6、MRR、revision 正确率、来源链接率和无答案误召回；用 `--expected-split test` 强制本次运行只能读取封存测试集，避免把开发集结果误写成最终指标。它只评估检索，不把模型生成质量冒充为结果。真实 Zotero 用户库的长期使用数据尚未作为效果指标报告。

本地合成 smoke corpus（2 条可回答、2 条无答案）先用原始词面候选得到无答案误召回 1/2；加入 MemoryQA 使用的可解释词面覆盖门控后，Recall@6、MRR、revision 正确率和来源链接率仍为 1.00，无答案误召回降为 0/2。新增的模糊问题测试验证了“改写 1 次 + 回答 1 次”的调用上限和来源边界。这个结果只说明门控和补救流程在合成样本上有效，不能写成生产准确率；真实中文问法仍需持续扩充测试集。

门控默认要求覆盖 20% 的有效中文字符 n-gram，可通过 `RESEARCH_MEMORY_MIN_QUERY_COVERAGE` 调整；每次个人记录问答会把实际门槛写入 trace，评测脚本用 `--min-coverage` 固定同一配置。

建立真实个人记忆评测集时，可先运行：

```powershell
python benchmarks/create_memory_review_template.py --root . `
  --questions questions.json --output memory-review-template.json --backend multimodal
```

也可以从“仅笔记”问答历史自动提取去重问题：

```powershell
python benchmarks/create_memory_review_template.py --root . `
  --qa-jobs .data/zotero/qa_jobs.sqlite3 --job-limit 50 `
  --output memory-review-from-history.json
```

该入口只接受 `scope=notes` 的已完成任务，不会把论文原文问答混入个人记忆评测；输出仍需人工确认当前记录的 entity、revision 和摘录。

它只检索当前有效笔记，输出带 `entity_id`、revision、类型和来源链接的 `candidate_records`；`expected` 与 `no_answer` 保持空值，必须人工核对后再删除候选字段并运行 `validate_personal_memory_dataset.py`。模板不会调用生成模型，也不会把论文原文提升为个人记录。

人工确认后可用 `benchmarks/approve_personal_memory_candidates.py` 封存评测集。它只接受个人记录候选，要求审核文件逐条填写 `approve/reject`、非空说明、`expected` 或 `no_answer`；封存前会再次检查当前 SQLite 中的记录、revision、确认状态和摘录。论文原文或 `scope=both` 候选会直接拒绝，记录更新后旧候选也会因 revision 过期而失败。

```powershell
python benchmarks/approve_personal_memory_candidates.py `
  --candidates memory-review-from-history.json `
  --review memory-review-approved.json `
  --root . --output memory-development.json --split development
```

这一步仍需要人工核对，但只核对自动筛选出的少量候选，不需要为每次日常问答手工建立数据集。

如果新部署还没有个人记录，可以让持续检查明确报告“暂无样本”，而不是直接失败：

```powershell
python benchmarks/create_memory_review_template.py --root . `
  --qa-jobs .data/zotero/qa_jobs.sqlite3 --allow-empty `
  --output output/memory-review-empty.json
```

输出的 `status=empty_history` 只是流水线连通性结果，不是可用于评测的空答案集。

历史读取和反馈导出使用 SQLite `mode=ro`：不会迁移数据库，也不会把在线任务标成中断。`--allow-empty` 只允许现存任务库没有合适问题；路径错误或缺少任务表仍报错，避免悄悄创建空库。
