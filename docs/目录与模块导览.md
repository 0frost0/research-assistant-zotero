# 目录与模块导览

本次整理按职责划分 Python 包，保持检索策略、模型、数据格式和工作流行为。阅读时先掌握模块如何传递数据，再进入某个实现文件，不需要从根目录逐个读完。

## 3. 为什么这样划分

`ingestion` 解决“PDF 中有什么”，`retrieval` 解决“哪些内容与问题有关”，`agents` 解决“如何基于证据分析”。三者变化原因不同：更换解析器主要改解析适配；更换嵌入模型主要改模型适配与索引契约；改变 Agent 分工主要改工作流。

`web` 负责 HTTP 参数和响应，`storage` 负责证据与表格持久化。这样可以用临时数据库和模拟模型测试工作流，不必每次都启动远程 GPU、打开浏览器或支付模型费用。

这是单体项目中的模块化，不是微服务拆分，也不是把文件搬进文件夹就自动消除了耦合。当前 `knowledge_base.py` 仍编排解析与检索；对照状态存储仍在 `web/comparison_api.py` 内，源版本工具仍由计划模块提供。保留这些现有边界避免在目录整理中同时改变业务行为，后续可以单独评估拆分。

## 4. 路径为什么单独管理

[core/paths.py](../research_assistant/core/paths.py) 根据自身位置确定项目根目录。网页、命令行、基础评测和 MinerU 从这里取得项目路径。这样即使从其他终端目录启动，仍使用同一份 `library/`、`.data/` 和 `.cache/`，不会在业务子目录里意外创建第二套库。

网页资源搬到了 `research_assistant/web/static/`，浏览器仍访问原来的 `/static/...` URL。根目录的 `web_app.py` 支持原有 `python web_app.py` 和 `uvicorn web_app:app`；内部源码使用完整包导入，不再依赖根目录散落模块。

运维脚本现位于 `scripts/`，从脚本目录的上一级定位项目。Qdrant Compose 仍绑定原有 external 命名卷。远程嵌入源码是独立部署材料：见 [部署说明](../deployment/README.md)，本次本地整理不代表已搬动远程服务器目录。

## 5. 什么能清理，什么要保留

- `__pycache__` 和 `.pyc` 是 Python 运行时生成的缓存，可删除，下次运行会再生成。
- `tests/` 是回归测试源代码，使用临时资料或模拟模型检查行为；原 111 项全部保留，加上本地存活及字段兼容测试，当前 113 项全部通过。原 `tests.py` 更名为 `tests/test_core.py`。
- `benchmarks/` 的报告、JSON、人工/AI 审阅包是实验记录，可用于比较版本，不能因为它们带有 test/eval 含义就当作垃圾删除。基础 `eval_cases.json` 移到了 `benchmarks/datasets/`；其余历史实验文件维持路径和内容。
- `.cache/mineru/` 保存的图片路径会被证据库引用，`.data/` 保存历史和评测，`library/` 是原件。它们不是本次要删除的中间产物。
- `.benchmark_envs/` 和 `.benchmark_models/` 虽然名字含 benchmark，仍有解析器依赖它们，不在本次清理范围内。

阅读顺序建议：本导览 → 项目介绍 → 感兴趣的工作流 → 对应测试。测试的价值是具体说明“哪些行为不能被改坏”，例如复核失败不能伪装成通过。
