# 第三阶段：公开权重与数据核查

2026-11-17 更新。**结论：有可用的公开数据路线，不必自建标签或等待 RINSE 作者；S2G-Judge 有真实权重，但许可与基础模型访问仍是门槛。MuSiQue-Full 上 Qwen3-8B 的 evidence-chain-audit 在 held-out 上复现相对收益，但绝对充分召回仍不足以进入生产。SURE-RAG 的论文方法可参考，但当前未核验出可直接复用的官方代码、权重或 HotpotQA-RAG v3 下载入口。** 本轮没有训练、提交、推送或部署，生产继续使用 `hybrid_rerank`。

### 本轮已验证的公开基线进展

- `benchmarks/run_public_sufficiency.py` 已冻结输入隔离、严格布尔 JSON 解析、失败计数、成对 bootstrap 和文件指纹；开发集 32 对，held-out 128 对，输入只含问题与原始完整段落。
- 开发集结果：direct → chain 的 balanced accuracy **57.81% → 68.75%**，充分召回 **34.38% → 40.63%**，不足误放行 **18.75% → 3.13%**；paired bootstrap 的 accuracy delta 95% 区间为 **[+3.13pp, +18.75pp]**。开发集满足预设相对收益条件，但绝对充分召回仍不足以作为生产门禁。
- held-out 已从远端回收并完成严格校验：**256 条输入 × 2 个 prompt = 512 条预测**，开发／held-out 的输入、模型文件、代码和推理配置指纹均符合冻结协议。
- held-out 结果：direct → chain 的 balanced accuracy **61.72% → 73.05%**，充分召回 **38.28% → 50.78%**，不足误放行 **14.84% → 4.69%**；paired bootstrap accuracy delta 95% 区间 **[+6.25pp, +16.80pp]**，预设相对收益条件通过。chain 有 **4/256（1.56%）** 格式无效，按协议计错；direct 全部有效。
- held-out 成对转移：充分类 29 改善、13 退步、36 两侧正确、50 两侧错误；不足类 14 改善、1 退步、108 两侧正确、5 两侧错误。chain 中位生成时间约 **4.59s**，direct 约 **0.57s**；这是顺序生成诊断，不是 Zotero 端到端延迟。
- 结果收据与汇总：`output/public-sufficiency-v1-20261115/receipt-20261116-180017/scored/summary.json`。这证明同分布公开数据上的相对收益已复制，不证明 Zotero 科研文献上的充分性准确率；`production_ready` 保持 false。
- reserve pilot 已完成：从未使用的 reserve 固定抽取 32 对，direct／原 chain／`chain_strict` 在同一 64 条输入上各运行一次。原 chain balanced accuracy **70.31%**、充分召回 **40.63%**、不足误放行 **0%**、格式失败 **0/64**；`chain_strict` 为 **73.44%**、**56.25%**、**9.38%**、**1/64**。strict 相对原 chain 的 paired bootstrap accuracy delta 95% 区间为 **[-6.25pp,+10.94pp]**，且不足类退步，预设收益条件未通过，故不采用 strict 变体。收据及三臂报告：`output/public-sufficiency-v1-20261115/pilot-chain-strict-v1/pilot-score.json`。
- Zotero 迁移边界审计已完成：`benchmarks/audit_zotero_sufficiency_transfer.py` 对冻结的 52 题／两种检索臂共 104 条记录做只读校验。48 个正例包含 57 个指定锚点；legacy 与 hybrid 的候选池均为 20 条、52/52 次精排成功。Top-6 锚点覆盖代理为 legacy **89.47%（锚点）／87.50%（题目全覆盖）**，hybrid **89.47%／87.50%**；4 个 absence probe 未计分。报告：`output/qwen-zotero-questions-20261110/sufficiency-transfer-audit.json`。这些数字不是充分性准确率，也没有调用回答模型或改生产配置。
- 新增 `benchmarks/finalize_public_sufficiency.py` 与 `benchmarks/collect_public_sufficiency.ps1`：回收后会校验 split、模型／代码指纹、完整收据、重复行、输入重叠与篡改，并分别输出开发集和 held-out 分数。两个脚本已通过编译；公开充分性测试 **6/6** 通过；临时完整／篡改收据检查均符合预期。
- 下一步若要得到 Zotero 充分性质量结论，必须先取得独立的 sufficiency gold 或用户授权的公开数据迁移协议；当前只保留锚点覆盖审计，生产继续 `hybrid_rerank`。

### 证据证书机制 pilot（已完成，不采用）

- 已实现 `benchmarks/sufficiency_certificate.py`：提议短答案及 claim/document/quote → 精确原文子串校验 → 新会话逐项支持性及问题完整性核验。第二阶段仍是同一 Qwen3-8B，调用隔离不代表模型独立；引句命中也不等于逻辑蕴含。
- skip=128 的新 reserve 32 对，完整上下文，chain／certificate 交替顺序，输出目录 `output/public-sufficiency-v1-20261115/pilot-certificate-v1/`。推理前协议见该目录 `protocol.md`；额外 token／调用预算单独记录。
- 只做推理实验；中间答案与证书不是新训练标签。评分重放阶段记录，格式失败计错，报告提议阶段消融、核验器各类别拦截和调用成本。
- 128/128 条预测完整回收，源切片、收据、配置及逐阶段重放通过。chain→certificate：balanced accuracy **68.75%→56.25%**，充分召回 **46.88%→21.88%**，实际不足误放行 **9.38%→6.25%**，含无效的不足类失败率均 **9.38%**；certificate 有 **1/64** 格式失败。paired accuracy delta 95% 区间 **[-21.88pp,-4.69pp]**，本切片明确退步，不采用。
- 损失定位：26 条引句检查失败（充分12／不足14），不是仅空白差异；共45处非逐字匹配、1处引用了错误文档。37条进入语义核验，其中充分样本误拒13、放行7，不足样本拒绝15、误放行2。提议阶段（含引句匹配）充分召回62.50%，实际误放行53.13%；不能把这项消融作为可用替代。
- 成本：certificate 共64次提议＋37次核验；生成22193 token（chain 9785）；中位逐样本推理 **8.92s**（chain **4.52s**）。计时是本次串行实验诊断，不是生产延迟。
- 收据与评分：上述目录 `run/`、`pilot-score.json`；无原文的引句失败诊断 `quote-failure-audit.json`。诊断不修改预测、不放宽匹配重算主分数。本地公开充分性与证书测试 **17/17**、编译检查通过。
- 结论：现模型下，生成证据链存在引句忠实性问题，同模型二次核验又损失召回；增加核验步骤没有实现双目标。原 chain 保留研究候选。下一方向应先核查可直接使用的公开 judge／关系蕴含权重及科学文献域适用性，再决定实验；尚未启动新训练或下一轮模型运行。

## 2. 最匹配的权重候选：S2G-Judge

来源：[ACL 2026 论文](https://aclanthology.org/2026.acl-long.1185/)、[作者仓库](https://github.com/nianaaa/S2G-RAG)。固定 commit：`a891e5652a8521e4ddbea1fa76771ff6819819e7`。

### 已实际验证

- 完整下载 `LoraCheckpoint/adapter_model.safetensors`：**97,307,544字节**，不是LFS指针；392个F32张量、24,313,856个参数，张量数据范围连续、大小一致。重新计算Git blob SHA1，与固定树中的 `b54cb52dba3f4459880bd9f7d6017f578946a392` 一致。
- 文件SHA256：`5e2ba4e888f83887915efc9fb3d6d2826afd4c8aacc21568e8f401aa4f52674a`。
- `adapter_config.json` 为LoRA r16／alpha32，覆盖28层的7类projection；基础路径是作者本地 `/root/autodl-tmp/models/llama-3.2-3b-instruct`，未固定revision。架构尺寸与README声明的 **Llama-3.2-3B-Instruct** 相符；不是可挂在现有Qwen上的通用权重。
- 已下载并解析 `data/hotpotqa_lora/train.jsonl` **3,000条**，`validation.jsonl` **300条**。字段：`uid/id/turn/question/context/context_sha256/sufficient/gap_items/teacher_model`。
- 训练集充分1,000／不足2,000，验证集充分100／不足200；题目ID与题目文本无跨split重合，唯一共享context是空串。150／15条空证据，不可将其结果当复杂缺一跳表现。
- 全部记录标明教师为 `gpt-4o-mini`；这是**作者已发布的机器标签**，不是人工gold，更不需要我们重新生成。context哈希3,300/3,300一致。
- 原文推理函数 `call_suff_gate_batch` 的模型输入只有 question＋context，输出 `sufficient` 和结构化 `gap_items`，无需先生成答案。可以设计独立judge入口，不必接入整个BM25／Java／多轮检索／answer reasoner。

### 不能省略的限制

1. 固定仓库31个文件，**未找到LICENSE／COPYING／NOTICE，也未见README明确授予代码、adapter或派生标签再利用许可**。公开下载不等于许可明确；当前不复制到项目、不集成发布，不将其列为已解决授权的模型。
2. Meta官方基础模型API标记 `gated=manual`，许可 `llama3.2`；只读取元数据，不下载基础权重、不接受条款或绕过访问限制。远端已检查的常用模型目录与当前项目目录未找到Llama；这不是全服务器穷尽扫描，不能断言不存在。
3. README明确是 **retrained version with comparable performance**，不是原论文完全相同checkpoint；尚无本项目真实加载或质量结果。
4. 训练上下文是抽取后的英文 evidence sentences；我们的六段完整科研原文、中文问题属于迁移。不能承诺跨域收益。
5. 官方推理与训练prompt并非逐字相同；原parser有 `bool(parsed.get(...))`，字符串 `"false"` 会变True；tokenizer启用截断而未显式记录丢失证据。未来适配须严格bool／schema验证、记录长度及截断，不静默放行。
6. 官方QA评测默认只取前1,000个unique question IDs，指标是最终答案EM/F1，不是独立充分性判断质量；不能直接当阶段三验收。

**定位：任务高度匹配、权重真实存在的优先候选，但不是当前已可无条件使用／部署的成品。许可仍不明确时，跳过它，不再走索要产物路线。**

## 3. 许可明确的公开数据：MuSiQue-Full（首选）

- [官方仓库](https://github.com/StonyBrookNLP/musique)，固定commit `922ac98f19a201998dbdae6d7f2887a5258dbdeb`。官方README和LICENSE明确 **CC BY 4.0**。
- 这是 **MuSiQue-Full，不是只有可回答问题的MuSiQue-Ans**。同一问题配充分／不足的上下文，已有 `answerable` 标签；适合问题＋证据集合的生成前判断，不需我们删除段落造负例。
- 论文／README列出的Full train为39,876条（Ans train19,938条的成对版本）；本轮未全量下载train。已从公开镜像读取train前262,144字节并解析21条完整记录，确认原文与answerable字段可匿名访问；不把样本核验写成完整train完整性验证。
- 已完整下载并解析Full dev：**4,834条 = 2,417对**，充分／不足各2,417条；每对题目文本相同。字段包括 `question/paragraphs/answerable`，另有答案与分解仅供评测方使用。
- 大多数20段，但实际包含15–19段的记录，不能硬编码全是20段。原协议先用全部原始证据；选成六段后，原 `answerable=true` 不再保证成立，**禁止把旧标签直接搬给删减后的六段集合**。六段适配另报，不与原协议混算。
- 原始官方分发入口是Google Drive；本轮数据来自HF第三方镜像 [voidful/MuSiQue](https://huggingface.co/datasets/voidful/MuSiQue/tree/a7d9f9adf6191604fc67cde318ee1a86fcf7babc)，revision `a7d9f9adf6191604fc67cde318ee1a86fcf7babc`。已区分官方许可来源与镜像字节来源，尚未与官方Drive压缩包逐字比对。
- Full dev 59,422,562字节，SHA256 `8cab31d56a3a1c4ef491b205a8dab3f1ac9c66e472098c6cf1de4e20294f7a4a`。
- 官方还列有MuSiQue-Full的旧End2End／Select+Answer模型下载ID，但未实际核验这些Drive模型文件及老AllenNLP加载环境，因此不称为已确认可用的现成judge。

**定位：本轮已确认“公开可下载、许可明确、字段匹配”的主要数据路线；可先评测现有模型，若后续决定训练也只用原有公开train标签。** 官方提醒其源单跳数据可能与其他训练集重合，需遵守dev/test源问题ID排除清单，不宣称预训练无污染。

## 4. 其他候选的取舍

- [SufficientFacts](https://huggingface.co/datasets/copenlu/sufficient_facts)：数据卡声明MIT、2,600条人工标注诊断记录，只有test；输入是**待核验claim＋evidence**，不是开放问题。可作缺条件敏感性参考，不能直接充当本任务训练集或把claim当问题。
- [FaithEval-unanswerable](https://huggingface.co/datasets/Salesforce/FaithEval-unanswerable-v1.0)：卡与API确认2,492条test，原文缺答案的拒答压力测试；不是正负齐全训练集，不能单独检验“全部拒答”。数据卡强调research-only并链接使用政策；代码仓库Apache许可不能自动覆盖所有来源数据。不作为当前训练来源。
- [yjmsvma/flant5-large-sufficiency-classifier](https://huggingface.co/yjmsvma/flant5-large-sufficiency-classifier)：HF API确实列完整safetensors、tokenizer及handler，约783M参数；非只有付费endpoint。但模型卡未给训练数据、标签语义、充分性质量或明确派生权重许可。仅列次级候选，不因名称命中就采用。
- `yjmsvma/sufficiency-classifier-v3`／`VahanMartirosyanMBZUAI/information_sufficiency_classifier_llama_3.1_8B`：卡与API有LoRA，但主要是自动生成的Unsloth卡；缺训练协议与可复现输入输出依据，Apache标签也不能替代Llama基础许可。不优于S2G。
- `c-capova/sufficiency-model`：确实列critic `.pt` 和encoded dataset，但没有README／license及可还原原文推理的配置说明；不执行不明pickle，不采用。
- `AcidHunter/light-sufficiency-predictor`：卡明写 **DRAFT, not uploaded**，且预测的是某个摘要小模型的质量，不是问答证据充分性，淘汰。
- `p4ulbr4dl3y/ocrrag-sufficiency-data-v1`：公开JSONL与首批样本可访问，但缺明确许可，卡说明标签继承生成器answer/refusal variant；不当人工充分性gold，不作优先训练源。
- [Sufficient Context](https://github.com/hljoren/sufficientcontext)：公开判定标准与prompt，可以使用现有模型做**无需训练**的适配基线；论文Gemini autorater的93%不是本地Qwen效果，也不是已公开专用权重。
- Knowing Before Answering：已拿到的README仅介绍论文，当前没有核验出可用checkpoint／原文数据；不把论文方法当现成产物。

## 5. 推荐顺序与验收边界（尚未执行）

1. **先用MuSiQue-Full原有公开dev标签做现有模型的离线充分性基线**，不自建数据、不训练。冻结公开prompt与模型版本，输入仅question＋原始全部paragraphs；不把answer、support标记或question_decomposition交给judge。

## 7. SURE-RAG 官方资源复核（2026-11-17）

### 7.1 已核验事实

- 论文：[arXiv 2605.03534](https://arxiv.org/abs/2605.03534)，当前核验版本为 v2；论文源包 [arXiv e-print](https://arxiv.org/e-print/2605.03534v2) 只包含 TeX、参考文献、图片和 LaTeX 样式文件，没有 Python 源码、模型权重、预测文件或数据集文件。
- 源文档的可复现性段落写的是：在遵守源数据许可的前提下，作者**计划**发布处理后的 JSONL、split/config、预测和评测脚本；正文没有给出 GitHub、Hugging Face、Zenodo 或其他可下载入口。这里的“计划发布”不能记录为已经公开。
- 论文明确写明主实验需要训练 `DeBERTa-v3-base` pair verifier、训练 logistic aggregator，并使用 seeds 13/21/42；因此它不是拿到论文即可直接运行的无训练 judge。论文结果是作者在其自建的 HotpotQA-RAG v3 控制基准上的报告，不是当前项目已验证结果。
- HotpotQA-RAG v3 在论文中被描述为 4,026 条、900 个 question groups 的构造基准，但论文及源包没有提供下载 URL、固定文件、哈希、处理脚本或公开 split 文件。本轮检索 GitHub repository/code、Hugging Face dataset 和论文链接，未找到可核验的公开数据入口；不能把论文中的数量当作本地可复现实验收据。
- 论文自己将该基准限定为 controlled、QA-derived，指出 shortcut artifact ratio 为 0.6816，且只验证 short-answer sufficiency；长篇科研文献、自然 RAG 日志和多 claim 覆盖仍是未验证边界。这与 Zotero 的六段完整论文、中文问题和个人文献记忆场景存在明显迁移差异。

### 7.2 `PROClaim` 误匹配排除

- 公开搜索结果曾把 `github.com/mnc13/PROClaim` 与 SURE-RAG 关联；本轮固定读取 GitHub API 的仓库树和 README，仓库标题是 **Courtroom-Style Multi-Agent Debate with Progressive RAG and Role-Switching for Controversial Claim Verification**，内容围绕 PubMed/COVID、FEVEROUS、HealthVer 和 SciFact 的争议 claim 核验。
- 固定 `main` 树（commit `30873e3d39dc3bef96baf8a0f2325559a46e1f56`）没有 SURE-RAG、HotpotQA-RAG v3、DeBERTa-v3-base verifier、logistic aggregator 或 SURE-RAG checkpoint；仓库也没有 release 或 GitHub Actions workflow，API 未返回许可证文件。
- 因此 `PROClaim` 只能作为搜索误匹配记录，不能写成 SURE-RAG 官方代码、数据或权重。没有复制该仓库到项目，也没有运行其代码。

### 7.3 路线决策

- **不采用 SURE-RAG 复现路线**：当前缺少可直接运行的官方实现、权重和 benchmark 数据入口；自行重建其训练数据／教师标签会违反本阶段硬约束。
- **不把论文指标写入项目结果**：`0.8951/0.9075` Macro-F1、30% coverage risk 和 HaluBench 数字只保留为论文报告，不能当作本项目实验或迁移证据。
- 仍保留其可借鉴的设计思想（集合级覆盖、支持／反驳／中性关系、shortcut 与 counterfactual 审计），但下一步只考虑已有公开数据和当前可用模型的无训练基线；若没有明确授权，不启动 SURE-RAG 式训练，不索要作者私有产物。
