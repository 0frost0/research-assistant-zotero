# 科研记忆助手：演示与面试主线

解决的问题：读过论文，不仅要找回原文，还要找回“当时我怎么理解、后来如何修正”。原文是证据，个人理解是有版本的观点，两者不能混用。

## 五分钟演示

1. 在 Zotero 同步一个小分类，问论文的方法或局限，打开引用核对原文。
2. 从证据创建一条“理解”或“疑问”，保留原文摘录与页码。
3. 选择“仅笔记”提问，展示个人记录回答及引用版本 v1。
4. 修改这条理解并保存为 v2。打开旧回答的引用：仍显示 v1，提示已有 v2，不悄悄改变历史依据。
5. 重新提问，核对使用 v2；归档后不再默认召回。编辑中刷新不会丢失文字。

前提：插件需要安装最新 XPI，后端模型已配置，分类已经同步。断网时不能保证远端笔记访问；模型不可用与后端不可用是两种情况。

## 三个值得讲的设计

| 问题 | 设计与取舍 | 可展示依据 |
| --- | --- | --- |
| 模型把个人观点当成论文事实 | 原文与笔记分路检索、分区回答；AI 草稿确认后才参与正式检索 | 同一问题的两类来源与引用 |
| 修改笔记后，旧回答的依据变了 | 追加 revision，乐观并发检查，引用绑定具体版本 | v1 回答与 v2 笔记并存，旧引用只读回看 |
| 检索不足时无限重试、花费不可控 | 有限改写与复核、明确调用上限、失败保留证据 | 任务状态与调用用量记录 |

## 复现入口

在安装了 `deployment/requirements-web.txt` 的 Python 环境及 Node 20+ 中，从仓库根目录执行：

```powershell
python -m unittest tests.test_knowledge tests.test_knowledge_qa tests.test_knowledge_jobs tests.test_job_readonly tests.test_public_sufficiency tests.test_sufficiency_certificate tests.test_zotero_build -q
node --test tests/zotero_bridge.test.cjs tests/zotero_workbench.test.cjs
python scripts/build_zotero_plugin.py
python benchmarks/build_personal_memory_smoke_corpus.py --root output/demo-memory-new
python benchmarks/evaluate_personal_memory.py --root output/demo-memory-new --dataset output/demo-memory-new/dataset.json --output output/demo-memory-new/report.json --apply-memory-gate --min-coverage 0.20 --expected-split test
```

每次使用新的 `--root`。这组命令验证离线契约、构建和合成检索，不调用回答模型，不代表原生操作或质量验收。真实模型原生复跑入口与依赖见 [真实库验收](acceptance/2026-11-07-真实库与Zotero10.md#原生-zotero-10)。

## 演示讲解与失败分支

- 展示笔记 v1 → v2 时解释：历史答案引用的是不可变 revision，当前检索读取最新有效版本；不是让模型自己判断记忆是否过期。
- 展示“仅笔记”无相关记录时解释：先做检索门控，最多一次改写；个人记录的范围自查不是独立事实证明。
- 展示模型不可用时解释：`unavailable` 与 `no_evidence` 不同；历史恢复读取已保存结果，不重复调用模型。
- 展示实验目录时只打开统计报告；用一项明确失败实验说明为什么没有替换默认算法。
